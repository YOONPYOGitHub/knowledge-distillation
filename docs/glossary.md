## 1. 지식 증류 핵심 용어

### Knowledge Distillation (지식 증류)

큰 모델(Teacher)이 학습한 "지식"을 작은 모델(Student)에 전달하는 기법.  
비유하면 **경험 많은 선배(Teacher)가 신입(Student)에게 노하우를 가르치는 것**과 같습니다.  
Student는 혼자 공부(Fine-tuning)하는 것보다 Teacher에게 배우면 더 좋은 성능을 냅니다.

### Teacher 모델

지식을 **가르치는** 큰 모델. KD 과정에서는 가중치가 고정됩니다(추론만 수행).  
KD 전에 `train_teacher.py`로 target 도메인에 Fine-tuning하면 더 품질 높은 soft target을 제공할 수 있습니다.  
이 프로젝트에서는 `gpt2` (124M 파라미터)를 기본 Teacher로 사용합니다.

### Student 모델

지식을 **배우는** 작은 모델. 증류 과정에서 가중치가 업데이트됩니다.  
이 프로젝트에서는 `distilgpt2` (82M 파라미터)를 기본 Student로 사용합니다.

### Hard Label (하드 레이블)

정답이 딱 하나만 표시된 레이블.  
예: 다음 단어가 "cat"일 확률 = 1, 나머지 = 0 → `[0, 0, 1, 0, 0]`  
일반적인 학습에서는 이 hard label만 사용합니다.

### Soft Label (소프트 레이블)

Teacher 모델이 출력하는 **확률 분포** 형태의 레이블.  
예: `[0.05, 0.15, 0.60, 0.12, 0.08]` — 정답 외에도 각 후보의 가능성이 담겨 있음.  
"cat"이 아닌 단어들 사이의 관계 정보(예: "dog"이 "car"보다 "cat"에 가깝다)가 포함되어 있어서, Student가 더 풍부한 지식을 학습할 수 있습니다.

### Temperature (온도, T)

Soft label의 **부드러운 정도**를 조절하는 값.
- **T = 1**: 기본값. 확률 분포가 뾰족함 (정답에 집중)
- **T = 3~5**: 분포가 부드러워져 클래스 간 관계 정보가 풍부해짐 → 증류에 적합
- **T = 10 이상**: 너무 평탄해져서 정보가 사라짐

비유: 시험 채점 기준을 느슨하게(T↑) 하면 1등과 2등의 점수 차이가 줄어들어 "누가 누구와 비슷한지"가 더 잘 보입니다.

### Alpha (α, 알파)

두 가지 Loss의 비율을 조절하는 가중치.
- `α = 1.0`: 정답(Hard Label)만으로 학습 (일반 학습과 동일)
- `α = 0.0`: Teacher의 Soft Label만으로 학습
- `α = 0.5` (기본): 정답과 Teacher 지식을 반반 섞어서 학습

### KD Loss (증류 손실)

증류 학습에서 사용하는 전체 Loss 수식:

```
KD Loss = α · CE(Student, 정답) + (1-α) · T² · KL(Student ∥ Teacher)
```

- 앞부분: Student가 정답을 맞추는 것 (일반 학습)
- 뒷부분: Student가 Teacher를 따라하는 것 (증류)
- 두 가지를 α 비율로 섞어서 동시에 학습합니다

### White-box Distillation

Teacher 모델의 **내부 출력(logit, 확률 분포)**에 접근 가능한 증류 방식.  
오픈소스 모델(GPT-2, LLaMA 등)에서 가능합니다. 이 프로젝트가 사용하는 방식입니다.

### Black-box Distillation

Teacher 모델의 **최종 텍스트 출력만** 볼 수 있는 증류 방식.  
GPT-4, Claude 같은 상용 API 모델에서 사용합니다. 내부 확률 분포를 볼 수 없으므로 생성된 텍스트를 학습 데이터로 사용합니다.

### 4-Way 비교

이 프로젝트의 핵심 실험 설계. 4가지 모델을 비교합니다:

| 모델 | 설명 | 역할 |
|------|------|------|
| **Teacher** | 큰 모델 (gpt2, 124M) Fine-tuned | 성능 상한선 (Upper Bound) |
| **Student (KD)** | 작은 모델 (distilgpt2, 82M), Teacher에게 배운 것 | 증류 효과 확인 |
| **Student (FT)** | 작은 모델 (distilgpt2, 82M), 혼자 공부한 것 | 일반 학습 기준선 |
| **Student (Base)** | 작은 모델 (distilgpt2, 82M), 아무 추가 학습 없음 | 성능 하한선 (Lower Bound) |

KD와 FT를 비교하면 **"Teacher에게 배운 것이 혼자 공부한 것보다 얼마나 나은가"**를 알 수 있습니다.

## 2. 딥러닝 기초 용어

### 파라미터 (Parameter)

모델 내부의 **학습 가능한 숫자(가중치)** 들. "774M 파라미터"는 모델 안에 약 7.74억 개의 숫자가 있다는 뜻입니다. 파라미터가 많을수록 모델이 크고, 더 복잡한 패턴을 학습할 수 있지만 메모리와 계산 비용이 증가합니다.

### 가중치 (Weight)

파라미터의 다른 말. 뉴런 사이의 연결 강도를 나타내는 숫자입니다. 학습하면서 이 값들이 조금씩 조정됩니다.

### Loss (손실)

모델의 예측이 정답에서 **얼마나 벗어났는지** 나타내는 숫자.  
Loss가 낮을수록 모델이 정답에 가까운 예측을 하고 있다는 뜻입니다.  
학습의 목표는 Loss를 최소화하는 것입니다.

### Cross-Entropy (CE, 교차 엔트로피)

분류 문제에서 가장 많이 쓰이는 Loss 함수.  
모델의 예측 확률 분포와 정답 사이의 차이를 측정합니다.  
값이 작을수록 모델이 정답에 가까운 확률을 출력하고 있다는 뜻입니다.

### KL Divergence (KL 발산)

두 확률 분포가 **얼마나 다른지** 측정하는 값.  
증류에서는 Teacher의 출력 분포와 Student의 출력 분포 사이의 차이를 측정합니다.  
값이 0에 가까우면 두 분포가 거의 동일하다는 뜻입니다.

- **Forward KL** `KL(Teacher ∥ Student)`: Student가 Teacher의 전체 분포를 커버하려 함 (mean-seeking)
- **Reverse KL** `KL(Student ∥ Teacher)`: Student가 Teacher의 핵심 부분에 집중 (mode-seeking)

### Logit (로짓)

모델이 softmax 함수를 통과하기 **직전**에 출력하는 원시 점수.  
각 단어(토큰)에 대한 점수이며, 이 점수를 softmax에 넣으면 확률이 됩니다.  
예: logit `[2.0, 1.0, 3.5, 0.5]` → softmax 후 확률 `[0.15, 0.05, 0.72, 0.03]`

### Softmax

logit 값들을 **0~1 사이의 확률**로 변환하는 함수.  
모든 확률의 합은 1이 됩니다. 큰 logit은 높은 확률, 작은 logit은 낮은 확률이 됩니다.

### Backpropagation (역전파)

Loss를 각 파라미터에 대해 미분하여, **어떤 방향으로 파라미터를 조정해야 Loss가 줄어드는지** 계산하는 과정. 모든 딥러닝 학습의 핵심 알고리즘입니다.

### Gradient (그래디언트)

Loss를 파라미터로 미분한 값. "이 파라미터를 이 방향으로 조금 바꾸면 Loss가 줄어든다"는 정보를 담고 있습니다. Backpropagation으로 계산됩니다.

### Optimizer (옵티마이저)

Gradient를 이용해 **실제로 파라미터를 업데이트하는 알고리즘**.
- **SGD**: 가장 기본적인 옵티마이저
- **Adam**: 학습률을 적응적으로 조절 (가장 많이 사용)
- **AdamW**: Adam + Weight Decay (이 프로젝트에서 사용)

### Overfitting (과적합)

모델이 학습 데이터를 **외워버려서** 새로운 데이터에는 성능이 낮아지는 현상.  
시험 문제를 달달 외우면 같은 문제는 잘 풀지만 처음 보는 문제는 못 푸는 것과 같습니다.

## 3. LLM / NLP 용어

### LLM (Large Language Model, 대형 언어 모델)

대량의 텍스트 데이터로 학습된 거대한 언어 모델.  
GPT-2, GPT-4, LLaMA, Qwen 등이 LLM에 해당합니다.  
"다음 단어 예측"을 기본 학습 방식으로 사용합니다.

### Transformer

현재 대부분의 LLM이 사용하는 딥러닝 아키텍처 (2017년 Google 제안).  
**Attention 메커니즘**을 핵심으로 하며, 긴 텍스트에서 멀리 떨어진 단어 간의 관계도 잘 파악합니다.

### Attention (어텐션)

입력의 각 부분이 **다른 부분에 얼마나 주목해야 하는지** 계산하는 메커니즘.  
예: "나는 어제 산 **사과**를 오늘 **먹었다**"에서, "먹었다"를 생성할 때 "사과"에 높은 attention을 줍니다.

### Auto-regressive (자기회귀)

이전에 생성한 단어들을 기반으로 **다음 단어를 하나씩** 생성하는 방식.  
GPT 계열 모델이 이 방식을 사용합니다.  
`"오늘"` → `"오늘 날씨"` → `"오늘 날씨 가"` → `"오늘 날씨 가 좋다"` 처럼 한 단어씩 순차적으로 생성합니다.

### Token (토큰)

모델이 텍스트를 처리하는 **최소 단위**.  
단어 단위가 아니라 서브워드(subword) 단위로 쪼갭니다.  
예: `"unhappiness"` → `["un", "happiness"]`, `"안녕하세요"` → `["안", "녕", "하", "세요"]`

### Tokenizer (토크나이저)

텍스트를 토큰으로 변환(또는 토큰을 텍스트로 복원)하는 도구.  
같은 모델 패밀리(예: GPT-2 계열)는 동일한 토크나이저를 공유합니다.  
**Teacher와 Student가 같은 토크나이저를 써야** 증류가 간단해집니다.

### Vocabulary (어휘, Vocab)

토크나이저가 알고 있는 **모든 토큰의 목록**.  
GPT-2의 vocab 크기는 50,257개입니다. 모델의 logit 출력 차원도 이 크기와 같습니다.

### Embedding (임베딩)

단어(토큰)를 **고차원 벡터(숫자 배열)**로 변환한 것.  
비슷한 의미의 단어는 비슷한 벡터 값을 갖게 됩니다.  
예: "왕" - "남자" + "여자" ≈ "여왕" (유명한 예시)

### Pre-training (사전학습)

대량의 텍스트 데이터(Wikipedia, 인터넷 등)로 모델을 **처음 학습**시키는 것.  
"다음 단어 예측" 하나만으로 범용 언어 능력을 학습합니다.  
GPT-2, LLaMA 등의 모델이 이미 사전학습된 상태로 공개되어 있습니다.

### Fine-tuning (파인튜닝)

사전학습된 모델을 **특정 태스크나 데이터**에 맞게 추가로 학습시키는 것.  
전체 모델을 처음부터 학습하는 것보다 훨씬 빠르고 적은 데이터로도 가능합니다.  
이 프로젝트의 "Student (FT)"가 Fine-tuning만 한 모델입니다.

### Inference (추론)

학습이 끝난 모델로 **실제 예측/생성**을 수행하는 것.  
학습과 달리 가중치를 업데이트하지 않으며, 이 프로젝트에서 Teacher 모델은 추론만 합니다.

### Context Length (컨텍스트 길이)

모델이 한 번에 처리할 수 있는 **최대 토큰 수**.  
GPT-2는 1024 토큰, LLaMA-2는 4096 토큰이 최대입니다.

### Padding (패딩)

길이가 다른 텍스트들을 같은 길이로 맞추기 위해 **빈칸(pad token)을 채워넣는** 전처리 방식.  
짧은 문장에 패딩이 대량 발생하면, 모델이 패딩 토큰을 예측하는 법을 학습하게 되어 PPL이 왜곡됩니다.  
이 프로젝트 초기에 패딩 방식을 사용했다가 Packing으로 교체했습니다.

```
"Hello world"  → [15496, 995, PAD, PAD, PAD]  ← 3개가 의미 없는 빈칸
"Hi"           → [17250, PAD, PAD, PAD, PAD]  ← 4개가 빈칸
```

### Packing (패킹)

모든 텍스트를 하나로 이어붙인 뒤 **고정 길이(max_seq_length)로 잘라내는** 전처리 방식.  
패딩이 전혀 없으므로 모든 토큰이 유의미한 학습 대상입니다.  
GPT-2, LLaMA 등 **Causal LM 학습의 표준 방식**이며, 이 프로젝트가 사용하는 방식입니다.

```
1단계: 모든 텍스트를 토크나이즈 후 연결
  [15496, 995, 17250, 11274, 8496, ...] (총 수만 개)

2단계: 256개씩 자르기
  chunk1: [15496, 995, ..., ] (256개, 전부 유의미)
  chunk2: [다음 256개]
  나머지가 256 미만이면 → 버림
```

## 4. 학습(Training) 관련 용어

### Epoch (에폭)

전체 학습 데이터를 **1번 순회**하는 것.  
"3 epochs" = 전체 데이터를 3번 반복하여 학습.

### Batch (배치)

한 번에 모델에 넣는 **데이터 묶음**.  
전체 데이터를 한 번에 넣을 수 없으므로<br>작은 덩어리(batch)로 나눠서 학습합니다.

### Batch Size (배치 크기)

한 배치에 포함되는 **데이터 샘플 수**.  
클수록 학습이 안정적이지만 GPU 메모리를 많이 씁니다.  
이 프로젝트 기본값: 8

### Learning Rate (학습률, lr)

파라미터를 업데이트할 때 **한 번에 얼마나 크게 바꿀지** 결정하는 값.
- **너무 크면**: 최적점을 지나쳐 Loss가 발산
- **너무 작으면**: 학습이 너무 느리거나 지역 최솟값에 갇힘
- 이 프로젝트 기본값: 5e-5 (= 0.00005)

### Warmup

학습 초기에 Learning Rate를 **0부터 서서히 올리는** 기법.  
갑자기 큰 학습률로 시작하면 학습이 불안정해질 수 있기 때문입니다.

### Weight Decay (가중치 감쇄)

큰 가중치에 **페널티**를 주어 파라미터 값이 너무 커지는 것을 방지.  
과적합(overfitting) 방지에 도움이 됩니다.

### Gradient Clipping (그래디언트 클리핑)

Gradient 값이 너무 커지면 학습이 폭발할 수 있는데, **최대값을 제한**하여 안정적으로 학습하게 하는 기법. 이 프로젝트 기본값: 1.0

### Gradient Accumulation (그래디언트 누적)

GPU 메모리가 부족해 큰 batch를 사용할 수 없을 때, 작은 배치의 gradient를 **여러 번 누적**한 뒤 한꺼번에 업데이트하여 큰 배치 효과를 내는 기법.

### Checkpoint (체크포인트)

학습 중간에 모델의 가중치를 **저장**해 둔 것.  
학습이 중단되어도 마지막 체크포인트부터 재개할 수 있고, 가장 성능이 좋았던 시점의 모델을 사용할 수 있습니다.

### DataLoader (데이터로더)

데이터를 배치 단위로 잘라서 모델에 **순서대로 공급**하는 도구.  
셔플(순서 섞기), 배치 생성, 병렬 로딩 등을 담당합니다.

---

## 5. 평가(Evaluation) 관련 용어

### Perplexity (퍼플렉시티, PPL)

언어 모델의 품질을 나타내는 **핵심 지표**. 값이 **낮을수록 좋습니다**.  
직관적으로 "다음 단어를 예측할 때 평균적으로 몇 개의 후보 중에서 고민하는가"를 의미합니다.
- PPL = 10: 평균 10개 후보 중에서 고민 → 꽤 잘 예측함
- PPL = 100: 평균 100개 후보 중에서 고민 → 예측이 어려움
- 수식: `PPL = exp(평균 Cross-Entropy Loss)`

### tokens/sec (초당 토큰 수)

모델이 1초에 생성하는 **토큰 수**. 추론 속도를 나타냅니다.  
크기가 큰 모델일수록 느리고, 작은 모델일수록 빠릅니다.

### Latency (지연시간)

하나의 요청에 대한 **응답 시간**. 보통 ms(밀리초) 단위.  
실시간 서비스에서는 낮은 latency가 중요합니다.

### Upper Bound / Lower Bound

- **Upper Bound (상한선)**: 이 실험에서 달성 가능한 최고 성능. Teacher 모델이 이 역할.
- **Lower Bound (하한선)**: 아무 노력도 하지 않았을 때의 성능. Student(Base)가 이 역할.

## 6. 하드웨어 / 최적화 용어

### GPU (Graphics Processing Unit)

원래 그래픽 처리용이지만, 딥러닝에서는 **병렬 행렬 연산**을 위해 사용.  
NVIDIA의 RTX 3090, A100, H100 등이 대표적입니다.

### VRAM (Video RAM)

GPU에 탑재된 **전용 메모리**. 모델과 학습 데이터가 여기에 올라갑니다.  
VRAM이 부족하면 큰 모델을 로드할 수 없거나 CUDA OOM 에러가 발생합니다.
- RTX 3060: 12GB
- RTX 3090/4090: 24GB
- A100: 40GB 또는 80GB

### CUDA

NVIDIA GPU에서 **딥러닝 연산**을 실행하기 위한 플랫폼.  
`torch.cuda.is_available()` → GPU를 사용할 수 있는지 확인하는 코드입니다.

### CUDA OOM (Out of Memory)

GPU 메모리가 부족하여 발생하는 에러.  
해결법: batch size 줄이기, FP16 사용, 양자화 적용 등.

### FP32 / FP16 / BF16

숫자를 저장하는 **정밀도(precision)**.
- **FP32** (32-bit): 기본 정밀도. 높은 정확도, 메모리 많이 사용
- **FP16** (16-bit): 메모리 절반. 대부분의 학습에서 충분
- **BF16** (Brain Float 16): Google이 개발. FP16보다 수치 안정성이 좋음

예: 774M 모델은 FP32 = ~3GB, FP16 = ~1.5GB

### Quantization (양자화)

모델의 숫자 정밀도를 **더 낮춰서** 메모리를 절약하는 기법.
- **8-bit**: FP32 대비 1/4 메모리 → Teacher 추론에 적합
- **4-bit**: 극도의 절약 → 7B 모델을 ~4GB VRAM으로 로드 가능

> ⚠️ Student 모델은 학습이 필요하므로 양자화하면 안 됩니다. Teacher(추론만)에만 적용하세요.

### device_map="auto"

Hugging Face에서 모델을 GPU에 **자동으로 할당**해주는 옵션.  
여러 GPU나 GPU+CPU 조합 시 자동으로 분배합니다.

### `from_pretrained()`

Hugging Face에서 **사전학습된 모델이나 토크나이저를 로드하는 함수**.  
최초 실행 시 인터넷에서 다운로드하고, 이후에는 로컬 캐시에서 로드합니다.

```python
model = AutoModelForCausalLM.from_pretrained("gpt2")

```

Facebook(Meta)이 개발한 **딥러닝 프레임워크**.  
모델 정의, 학습, 추론 등 모든 딥러닝 작업의 기반입니다.  
이 프로젝트에서 `torch`로 import합니다.

### transformers (라이브러리)

Hugging Face가 제공하는 **Transformer 모델 라이브러리**.  
GPT-2, LLaMA 등 수천 개 모델을 동일한 인터페이스로 사용할 수 있습니다.

### datasets (라이브러리)

Hugging Face가 제공하는 **데이터셋 라이브러리**.  
WikiText-2 등의 데이터셋을 한 줄로 다운로드·로드할 수 있습니다.

### accelerate (라이브러리)

Hugging Face가 제공하는 **분산/혼합정밀도 학습 지원 라이브러리**.  
GPU 할당, FP16 학습 등을 간편하게 설정합니다.

LLaMA, Mistral 등이 해당됩니다. GPT-2 계열은 게이트가 없어 바로 다운로드 가능합니다.

## 8. 수식 기호 정리

프로젝트 문서에서 자주 나오는 수식 기호를 정리합니다:

| 기호 | 이름 | 의미 |
|------|------|------|
| `α` | Alpha (알파) | CE Loss와 KD Loss의 비율 (0~1) |
| `T` | Temperature | soft label 부드러움 조절 (1~10) |
| `T²` | T-squared | Temperature 보정 계수 (gradient 크기 보정) |
| `CE` | Cross-Entropy | 정답과 예측 사이의 차이 (Loss 함수) |
| `KL` | KL Divergence | 두 확률 분포 사이의 차이 |
| `σ` | Sigma (시그마) | 여기서는 softmax 함수를 의미 |
| `z_t` | Teacher logit | Teacher 모델의 출력 (softmax 전) |
| `z_s` | Student logit | Student 모델의 출력 (softmax 전) |
| `y` | Label | 정답 레이블 |
| `ŷ` | y-hat | 모델의 예측값 |
| `∥` | 병렬(parallel) 기호 | KL(P ∥ Q)에서 "P 기준으로 Q와 비교" |
| `exp()` | 지수 함수 | e의 거듭제곱 (Perplexity 계산에 사용) |
| `↓` | 낮을수록 좋음 | Perplexity, Loss 등에 사용 |
| `↑` | 높을수록 좋음 | 정확도, 속도 등에 사용 |

### 전체 KD Loss 수식 해독

```
L_total = α · L_CE(y, ŷ_student) + (1 - α) · T² · KL(σ(z_t/T) ∥ σ(z_s/T))
```

| 부분 | 읽는 법 |
|------|--------|
| `L_total` | 전체 손실 (이것을 최소화하는 것이 목표) |
| `α · L_CE(y, ŷ_student)` | "α 비율만큼, Student의 예측이 정답과 다른 정도" |
| `(1 - α)` | "나머지 비율만큼" |
| `T²` | "Temperature 제곱으로 보정" |
| `σ(z_t/T)` | "Teacher logit을 T로 나누고 softmax 적용" = Teacher soft label |
| `σ(z_s/T)` | "Student logit을 T로 나누고 softmax 적용" = Student soft label |
| `KL(... ∥ ...)` | "두 soft label 사이의 차이" |
