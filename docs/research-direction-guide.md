# 연구 방향 가이드 — 모델 선택에 따른 경로

> 모델 패밀리 선택과 데이터 전략에 따라 연구 방향이 어떻게 달라지는지 정리

---

## 1. 핵심 결정 사항

프로젝트 시작 전 **2가지**를 먼저 결정해야 합니다:

1. **모델 패밀리** — GPT-2? LLaMA/Qwen? 그 외?
2. **데이터 전략** — General(범용)? 도메인 특화? 합성 데이터?

이 조합에 따라 연구의 성격, 난이도, 산출물이 완전히 달라집니다.

---

## 2. 모델 패밀리 선택지

모든 모델(GPT-2, LLaMA, Qwen 등)은 **Hugging Face Hub를 통해** 다운로드합니다.

### 현재 사용 가능한 모델 패밀리들

| 패밀리 | 예시 모델 | 출시 | 특징 |
|--------|----------|------|------|
| **GPT-2** | `gpt2`, `gpt2-large` | 2019 | 가볍고 실험 쉬움, 영어 중심 |
| **LLaMA** | `Llama-2-7b`, `TinyLlama-1.1B` | 2023~24 | 고성능, GPU 많이 필요 |
| **Qwen** | `Qwen2-7B`, `Qwen2-1.5B` | 2024 | 다국어(한중영), 최신 |
| **Phi** | `Phi-3-mini` (3.8B) | 2024 | Microsoft, 소형이지만 강력 |
| **Gemma** | `gemma-2b`, `gemma-7b` | 2024 | Google, 비교적 가벼움 |

## 3. 연구 경로 3가지

### 경로 A: GPT-2 유지 — "방법론 검증" 연구

| 항목 | 내용 |
|------|------|
| **연구 질문** | "지식 증류가 정말 효과 있나? 어떤 조건에서 잘 작동하나?" |
| **성격** | 학습/교육 목적, 알고리즘 이해, 논문 재현 |
| **데이터** | WikiText-2 (범용, 가벼움) |
| **실험 초점** | Temperature, Alpha, KL 방향 등 하이퍼파라미터 민감도 분석 |
| **GPU** | 12~24GB면 충분 |
| **기대 산출물** | "KD 작동 원리 이해 + 4-Way 비교 리포트" |

**할 수 있는 실험:**
- Temperature (1, 2, 3, 5, 10) 별 성능 변화
- Alpha (0.1 ~ 0.9) 별 최적점 탐색
- Forward KL vs Reverse KL 비교
- Layer 수/크기가 다른 Student 간 비교 (distilgpt2 vs gpt2)

**한계:** 2019년 모델이라 "최신 LLM 증류 연구"라고 하기엔 약함

---

### 경로 B: 최신 모델 (LLaMA/Qwen) — "실전 경량화" 연구

| 항목 | 내용 |
|------|------|
| **연구 질문** | "7B 모델의 능력을 1~2B 모델로 얼마나 압축할 수 있나?" |
| **성격** | 실전 응용, 배포·서빙 관점, 산업 적용 가능 |
| **데이터** | 범용 또는 도메인 특화 (한국어 포함 가능) |
| **실험 초점** | 압축률 vs 성능 트레이드오프, 실제 서빙 비용 절감 |
| **GPU** | 40~80GB 필요 (A100급) |
| **기대 산출물** | "7B → 1.5B 증류 시 성능 90% 유지, 추론 5x 빨라짐" 같은 실전 결과 |

**할 수 있는 실험:**
- Llama-2-7B → TinyLlama-1.1B 증류
- 한국어 데이터(KLUE 등)로 도메인 증류
- 양자화(4bit) + 증류 결합
- 실제 추론 속도, 배포 시나리오 벤치마크

**한계:** GPU 자원 크게 필요, 학습 시간 길어짐

---

### 경로 C: 하이브리드 — "GPT-2로 검증 후 최신 모델로 확장"

| 항목 | 내용 |
|------|------|
| **연구 질문** | "소규모로 최적 KD 설정을 찾고, 이를 대형 모델에 적용하면 통하는가?" |
| **성격** | 체계적 연구 (소→대 확장, MiniCPM 논문의 "Model Wind Tunnel" 방식) |
| **1단계** | GPT-2 (small→large)로 빠르게 실험, 최적 T/α/KL 방향 탐색 |
| **2단계** | 검증된 설정으로 LLaMA/Qwen 7B → 1.5B 증류 |
| **GPU** | 1단계: 12~24GB, 2단계: 40~80GB |
| **기대 산출물** | "소규모 실험 결과가 대규모에서도 재현되는가?" + 실전 결과 |

## 4. 경로 비교표

| | 경로 A (GPT-2) | 경로 B (최신모델) | 경로 C (하이브리드) |
|---|---|---|---|
| **난이도** | 낮음 | 높음 | 중간→높음 |
| **GPU 요구** | 12~24GB | 40~80GB | 단계별 |
| **실험 회전속도** | 빠름 (분 단위) | 느림 (시간 단위) | 1단계 빠름 |
| **논문/포트폴리오 가치** | 교육적 | 실전적 | 가장 높음 |
| **실용성** | 낮음 | 높음 | 높음 |
| **핵심 인사이트** | 알고리즘 이해 | 엔지니어링 최적화 | 스케일링 법칙 |
| **한국어 가능** | 어려움 | 가능 (Qwen, SOLAR 등) | 2단계에서 |

## 5. 데이터 전략 — 논문에서의 3가지 방식

### A. General Corpus 증류 (사전학습 단계)

> 참조: DistilBERT (2019), TinyBERT Stage 1

- Wikipedia, BookCorpus 등 **범용 데이터**로 증류
- Teacher의 "일반적인 언어 능력"을 Student에 전달
- **목적:** 범용 소형 모델 만들기

### B. Task-Specific 증류 (파인튜닝 단계)

> 참조: TinyBERT Stage 2, MiniLLM (2024)

- GLUE, SQuAD, WikiText 등 **특정 벤치마크/태스크 데이터**로 증류
- Teacher가 해당 태스크에서 잘하는 것을 Student에 전달
- **목적:** 특정 태스크에 최적화된 소형 모델

### C. Teacher 생성 합성 데이터 증류

> 참조: Zephyr (2023), Alpaca, Vicuna

- Teacher(GPT-4 등)가 **직접 생성한 텍스트**를 학습 데이터로 사용
- Student는 Teacher의 출력 텍스트만 보고 모방 (black-box)
- **목적:** API-only Teacher 활용, 고품질 instruction 데이터 확보

### 데이터 전략 비교

| 방식 | 데이터 | Teacher 접근 | 효과 | 난이도 |
|------|--------|-------------|------|--------|
| **A. General** | WikiText, OpenWebText 등 | White-box (logit) | 범용 능력 향상 | 중 |
| **B. Task-specific** | 특정 도메인/태스크 데이터 | White-box (logit) | 해당 태스크 크게 향상 | 중 |
| **C. 합성 데이터** | Teacher가 생성한 텍스트 | Black-box (출력만) | 실용적, 확장 쉬움 | 하 |

### 현재 프로젝트의 WikiText-2

**A번 (General Corpus)**에 해당합니다. WikiText-2는 Wikipedia 기반 범용 영어 텍스트입니다.

## 7. 결정 가이드

| 상황 | 추천 |
|------|------|
| "KD를 공부하고 이해하겠다" | **경로 A** (GPT-2 + WikiText-2) |
| "실제로 쓸 수 있는 경량 모델을 만들겠다" | **경로 B** (LLaMA/Qwen + 도메인 데이터) |

| GPU 12~24GB만 있다 | **경로 A** 또는 **경로 C 1단계** |
| GPU 40GB+ 있다 | **경로 B** 또는 **경로 C 전체** |
| 한국어 모델이 필요하다 | **경로 B** (Qwen, SOLAR 등) |
