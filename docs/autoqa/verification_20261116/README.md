# 2026-11-16 온디바이스 두 버전 채점 기록

팀이 올린 온디바이스 온담 두 버전과 ChatGPT를 같은 질문으로 견줬다.
채점 모델은 Opus 5.5로 바꿨다(11/15까지는 Sonnet 5.5).

## 무엇을 견줬나

| 이름 | 무엇 | 답 받은 날 |
|---|---|---|
| 검색 있는 온담 | Qwen3.5-4B + 지식 검색(Qwen 임베딩·OpenSearch·BGE 재순위) | 11/16 |
| 검색 없는 온담 | 같은 Qwen3.5-4B, 지식 검색 없음 | 11/16 |
| ChatGPT | 로그인 안 한 무료 기본 — 11/15에 받은 답을 다시 채점 | 11/15 |

- 비교는 두 가지다. ① 검색 있음 대 검색 없음 ② 검색 있음 대 ChatGPT.
- 검색 있는 온담 서버가 11/17 0시쯤 꺼져 109문항 중 100문항만 받았다.
- 못 받은 9문항은 SC-S40과 SC-W01~W08이다(영양제 1, 복지 문의 8). 그래서 세 곳 모두 이 100문항으로 견줬다.

  - 나란히 고른 비율 16%(가장 나쁘게 보면 10%).

- 답 하나를 기다린 시간(가운데 값): 검색 있음 122초, 검색 없음 4초. 시험 서버에서 잰 값이다.

## 채점기를 바꾸며 다시 잰 것

- 채점기 시험(Opus 5.5)
  - 일부러 심은 결함 90/91을 잡았다.
  - 좋은 답 117/117을 그대로 통과시켰다.
  - 결함 종류 60/60을 맞게 짚었다.
  - 놓친 1건(SC-M10 '괜찮다'고 안심시킨 답 → Fix로 잡음)은 Sonnet 때와 같다.
- 같은 답을 두 번 채점하면 판정이 일부 갈린다. 이번에는 318개 중 23개가 갈렸다(Sonnet 11/15: 218개 중 9개).

## 진행하며 고친 것

- 답 받기는 한 문항씩 바로 저장하고, 멈추면 `--resume`으로 이어 받는다.
- 오류가 계속되는 문항은 `--keep-going`으로 건너뛰고 나중에 다시 묻는다.
- 결정 룰 FMT-ECHO가 목록 제목 "**65 세 이상 어르신:**"을 대화 차례 표시로 잘못 잡았다. 이제 줄 맨 앞일 때만 센다.
- 나란히 비교에 `--basis`를 더했다. 검색 없는 온담은 출처 칸이 있어도 출처를 낼 수 없어서, 검색 있음 대 검색 없음은 `--basis common`(공통 기준)으로 셌다.
- PATH의 `claude`가 5월 판(2.1.145)이라 Opus 5.5를 못 불렀다. 채점은 데스크톱 앱의 새 판(2.1.325) 사본으로 했다(`SILVERCARE_CLAUDE_BIN`).
