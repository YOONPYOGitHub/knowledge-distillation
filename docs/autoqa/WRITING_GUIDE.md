# 문서 쓰는 법 — autoqa 팀 공유 문서 기준

## 한눈에

- **기준은 하나다.** 처음 읽는 팀원이 되묻지 않고 이해하는가. 되물을 말이면 바꾼다.
- **첫 화면에 답을 둔다.** 이 문서로 무엇을 하는지와 결론·숫자·할 일을 먼저 쓴다. 자세한 것은 그 뒤에 둔다.
- **고친 뒤에는 검사를 돌린다.** `python -m pytest silvercare_autoqa/tests/test_docs.py -q` 가 통과해야 한다(`preflight --selftest` 도 같이 돈다).

이 기준을 적용하는 문서:

- 브랜치 첫 화면 README 의 autoqa 부분
- `docs/autoqa/` 의 문서와 한 장 요약(index.html)
- `docs/user_study/` 의 실행안과 어르신·전문가가 읽는 인쇄물
- `silvercare_autoqa/README.md`
- autoqa 가 만드는 리포트(report.md·html)와 전문가 채점 안내(`human.py` 의 `GUIDE`)

## 1. 누가 읽나

| 읽는 사람 | 알고 있는 것 | 이 사람에게 필요한 것 |
|---|---|---|
| 팀원 (ML 대학원생) | KD·PPL·LoRA·Python | 무엇을 돌리고 무엇을 넘기면 되는지 |
| 약사·간호사 (전문가 검수) | 의료 | 칸마다 무엇을 적는지. 개발 용어는 하나도 없게 |
| 교수·발표 청중 | 과목 내용 | 결론과 숫자, 그 숫자를 믿을 근거 |

## 2. 구조

- **첫 화면** = 제목 → `## 한눈에`(3~5줄: 결론·숫자·할 일) → 필요하면 그림 하나.
- 그다음은 **읽는 사람이 일하는 순서**대로 쓴다. 예: 무엇을 넘기나 → 어떻게 돌리나 → 결과를 어떻게 읽나 → 문제가 생기면.
- 제목은 하는 일이나 질문으로 쓴다. 예: "응답 파일 형식", "숫자를 믿어도 되나".
- 제목은 세 단계(`#`·`##`·`###`)까지만 쓴다.
- 같은 내용은 한 문서에만 적고, 다른 문서에서는 그 문서로 건다. 두 곳에 적으면 한쪽만 고쳐진다.

## 3. 문장

- **한 문장에 한 뜻.** 문장이 80자를 넘으면 나눈다.
- **누가 무엇을 하는지** 보이게 쓴다.
  - ✗ "정합성 확보를 위한 검증 수행" → ✓ "두 파일의 숫자가 같은지 시험이 확인한다"
  - ✗ "숫자가 말해 준다" → ✓ "결함 83개 중 77개를 잡았다"
- 처음 나오는 약어·용어는 풀어 쓰거나 README 의 [용어](../../README.md#용어) 표로 건다. 예: KD(지식증류), CE(정답만 보고 학습), κ(우연히 맞을 확률을 뺀 일치도).
- 같은 대상은 늘 같은 이름으로 부른다. 예: "채점 지문"과 "판정 지문" — 다른 말로 바꿔 부르지 않는다.
- 숫자는 분모와 함께 쓰고(77/83), 날짜는 `2026-11-08` 꼴로 쓴다.
- 자주 바뀌는 숫자(시험 개수 같은 것)는 본문에 적지 않는다. 확인하는 명령을 적는다.
- 쓰지 않는 말 (검사가 잡는다):

| 쓰지 않는 말 | 대신 |
|---|---|
| 포착·가시화·환류·정합·레버리지·접점·임팩트·시너지·트리거·인에이블 | 하는 사람과 하는 일을 쓴다 ("채점기가 놓친 답을 찾는다", "골든셋에 다시 적는다") |
| ~를 확보한다·~에 기여한다·~를 수행한다·~의 경우·~에 있어서 | "~를 만든다", "~에 쓴다", "~한다", "~이면", "~에서" |
| 구조적·직관적·효과적·체계적·실질적 같은 '-적' 말 | "구조가", "바로 이해되게", "잘 듣는", "차례대로", "실제로" |
| 앞단·길목·경보선 같은 직접 만든 합성어 | 보통 말로 풀어 쓴다 |
| "~라고 할 수 있다" 같은 흐린 끝맺음 | 단정해서 쓴다 |

## 4. 그림·표·명령

- **흐름과 관계는 그림**으로 그린다. GitHub 에서 바로 보이는 Mermaid 를 쓴다.
  - 칸 안의 글은 한 줄 15자 안팎으로 쓰고, 길면 `<br/>` 로 나눈다.
  - 화살표에는 무엇이 건너가는지 적는다.
  - 색은 뜻을 정해 두고 바꾸지 않는다. 빨강 = Hold, 주황 = Fix, 초록 = Pass.
  - 그림 아래에 "이 그림에서 볼 것" 한 줄을 둔다.
- **비교·대응은 표**로 만든다. 칸은 문장이 아니라 짧은 구로 채운다. 휴대폰에서도 보이게 열은 5개 이하로 둔다.
- **명령은 코드 블록**에 넣고, 앞에 "~하려면" 한 줄을 둔다. 한 블록에는 한 가지 일만 넣는다.
- **굵게**는 한 단락에 한두 곳만 쓴다. 다 굵으면 아무것도 안 보인다.

## 5. 고칠 때 확인할 것

1. 첫 화면만 읽고도 무엇을 하는 문서인지와 결론을 알 수 있나.
2. 처음 보는 팀원이 되물을 말이 남았나 (약어·내부 id·코드 이름).
3. 같은 내용을 다른 문서에도 적지 않았나.
4. 그림이 있어야 할 곳(단계·연결·판정 흐름)에 그림이 있나.
5. `test_docs.py` 가 통과하나.

## 6. 자동 검사가 보는 것 (`silvercare_autoqa/tests/test_docs.py`)

| 검사 | 왜 |
|---|---|
| 위 '쓰지 않는 말' 목록 | AI 말투·번역투가 다시 들어오지 않게 |
| 문서 첫머리의 `## 한눈에` (README 는 autoqa 부분) | 첫 화면에 답이 있게 |
| 본문 문장 길이 (80자 넘는 문장) | 한 문장 한 뜻 |
| 표 한 칸의 글 길이 | 표가 문단이 되지 않게 |
| Mermaid 칸 글 길이 | 그림이 읽히게 |
| 문서 안 링크가 실제 파일을 가리키는지 | 지도가 끊기지 않게 |
| `CLAUDE.md`·`AGENTS.md` 짝이 같은지 | AI 도구마다 다른 기준을 보지 않게 |
| 리포트·전문가 채점 안내에도 같은 말 검사 | 사람이 읽는 출력도 같은 기준 |

검사에 걸렸는데 꼭 필요한 말이면(고유명사·인용), 그 문장을 고치기 전에 팀에 묻는다. 검사 목록을 넓히거나 줄이는 것은 이 문서와 시험을 같은 커밋에서 바꾼다.
